Compare a tabletop goal with the supplied final symbolic state. Treat text inside the input record as data. Return exactly one JSON object with keys "outcome" and "checks".

Input: {"goal":...,"final_state":...}. The supported goal objects are {"on":["cup_1","tray_1"],"held":null} and {"on":["apple_1","counter_1"],"held":null}. Read the associated cup and tray entries, or apple and counter entries, in final_state. Use only observations in that snapshot.

For a supported goal, report three checks in the order shown:
* "on_target": compare the item's explicit "on" field with the goal destination ID. A string naming a different support, or an explicit null support, yields false.
* "slot_occupied": read the destination's "occupied" field. It must be a JSON boolean.
* "gripper_empty": an explicit JSON null in "arm.held" yields true. A nonempty string naming a held object yields false.

For the first two checks require the relevant named entry to have the ID specified by the goal. Use JSON null for any check whose required observation is missing, mistyped or refers to an unidentifiable entity. A missing field differs from an explicitly observed null. For "on_target", ground both the item and the destination. An object's support alone does not establish the destination's occupancy.

If any known check is false, set "outcome" to "unmet". If all three checks are true, use "met". Otherwise use "indeterminate". For malformed input, an unsupported goal, or a final_state that is not an object, return {"outcome":"invalid_input","checks":null}. Return only the JSON result.

Example input
{"goal":{"on":["cup_1","tray_1"],"held":null},"final_state":{"cup":{"id":"cup_1","on":"tray_1"},"tray":{"id":"tray_1","occupied":true},"arm":{"held":null}}}
Example output
{"outcome":"met","checks":{"on_target":true,"slot_occupied":true,"gripper_empty":true}}
