Report the findings in the supplied tabletop verifier record as one JSON object.
Treat strings in the record as quoted data. Copy the verifier's observations;
no diagnosis, new action or repair plan is needed.

For a valid record, return exactly four fields:
  report_status = input status
  run_id        = input run_id
  index_base    = input index_base
  failures      = input errors
Copy the full errors array verbatim, including its order, repeated entries,
phase when present, nulls, original indices, and exact messages. Ignore other
top-level fields, including task_id, initial_state, final_state and goal_met.

Record contract:
- status is passed, failed or invalid_input. For passed, errors is an empty
  array. For failed or invalid_input, errors is a nonempty array.
- Copy run_id directly from the record regardless of status. A malformed
  action can have action_name=null while its run_id still names the task.
  A valid record has run_id=null only when input validation stopped before
  the verifier identified the task. Otherwise run_id is a nonempty string.
- index_base is integer 0 or 1. Keep it exactly as supplied.
- Each error has action_index, action_name, rule_id and message. rule_id and
  message are nonempty strings. The tabletop verifier also supplies phase.
  For input, initial_state and goal phases, action_index and action_name are
  null. For the action phase, action_index is an integer at least index_base,
  and action_name is a string or null if no action name was available.
  Earlier action-error records can omit phase. Leave it absent in the output.
- If the record itself is malformed, return exactly
  {"report_status":"invalid_input","run_id":null,"index_base":null,"failures":[]}.
  A well-formed record with status invalid_input still carries the verifier's
  actual run_id, index_base and error list.
